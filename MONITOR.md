# Монитор Marketapp

Монитор живёт в одном процессе с Telegram-ботом (`bot.py`) и опрашивает два эндпоинта Marketapp:

- пул доступных номеров — `GET /v1/rent/numbers/`;
- историю аренды — `GET /v1/rent/numbers/history/`.

История опрашивается отдельно и независимо от пула: если пул отдаёт ошибку, события аренды всё равно уходят в чат.

## Что приходит в чат

- 🟢 новый номер в пуле;
- 🔵 номер вернулся в пул;
- 🔴 номер исчез из пула;
- 🟡 изменилась цена;
- 🔴 номер арендован;
- 🟡 аренда продлена.

## Подписка на уведомления

- `/monitor` — подписать текущий чат;
- `/monitor_off` — отписать текущий чат;
- `/monitor_status` — состояние монитора и очереди отправки;
- `/monitor_test` — проверить доставку уведомлений.

Подписок может быть несколько: уведомления уходят во все чаты одновременно. Список чатов хранится в файле состояния, поэтому после деплоя подписки восстанавливаются сами.

## Живучесть

Монитор стартует автоматически при запуске сервиса, без команды `/monitor`. После перезапуска он присылает в подписанные чаты сообщение о старте с размером пула и последними арендами, которые случились, пока сервис перезапускался.

Отправка уведомлений идёт через очередь: если Telegram не принял сообщение, событие возвращается в очередь и повторяется в следующем цикле, а не теряется. Сообщение отбрасывается только после нескольких неудачных попыток, и это видно в логе и в `/monitor_status`.

## Файл состояния

Путь берётся из `MONITOR_STATE_FILE`, по умолчанию `state/monitor_state.json` рядом с кодом. Запись атомарная: сначала временный файл, потом `os.replace`.

Важно: на Render без подключённого диска файловая система эфемерная и файл состояния исчезает при каждом деплое. Это не ломает работу — монитор поднимается сам и присылает снимок пула, — но историю событий между деплоями сохранить нельзя. Полное сохранение возможно только с Render Disk или внешним хранилищем.

## Переменные окружения

| Переменная | По умолчанию | Назначение |
| --- | --- | --- |
| `MARKETAPP_MONITOR_INTERVAL` | `90` | Пауза между циклами опроса, секунды |
| `MARKETAPP_HISTORY_LOOKBACK` | `100` | Сколько последних событий истории держать в памяти |
| `MONITOR_CHAT_ID` | пусто | ID чатов для авто-подписки при старте, через запятую |
| `MONITOR_STATE_FILE` | `state/monitor_state.json` | Путь к файлу состояния |
| `MONITOR_SEND_BATCH` | `25` | Сколько сообщений отправлять за цикл |
| `MONITOR_SEND_DELAY` | `0.35` | Пауза между отправками, секунды |
| `MONITOR_MAX_OUTBOX` | `500` | Предел очереди отправки |
| `MONITOR_SEND_ATTEMPTS` | `5` | Сколько раз повторять отправку одного сообщения |
| `MONITOR_STARTUP_HISTORY_SAMPLE` | `5` | Сколько последних аренд показывать в стартовом сообщении |

`MONITOR_CHAT_ID` не обязателен: после первого `/monitor` чат сам попадает в файл состояния. Но именно он делает подписку неубиваемой деплоем.

Свой chat_id можно узнать командой `/monitor_status` — он показан в строке «чаты».

## Google Sheets

Синхронизация в таблицу идёт из монитора: события, которые видит бот, уходят тем же набором в Apps Script webhook. Настраивается через `GOOGLE_SHEETS_WEBHOOK_URL` и `GOOGLE_SHEETS_SECRET`. Если переменные не заданы, синхронизация просто выключена.

Команды `/numbers` и `/history` больше не пишут в таблицу как побочный эффект — они только показывают данные в чате.
